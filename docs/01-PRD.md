# WordQuest 产品需求文档（PRD）v1.0

- 状态：Draft for implementation / 可进入 MVP 开发
- 产品阶段：单用户家庭验证
- 目标平台：iPad 优先，手机兼容，PWA
- 内容基线：524 原始教材条目；471 去重词/词块；MVP30 = Animal Kingdom

---

# 1. 产品定义

## 1.1 一句话定义

WordQuest 是一个面向 8–9 岁儿童的英语词汇冒险游戏：孩子通过探索、听音、寻找、拖拽、拼词和小故事完成任务，在游戏推进中把课本词汇从“见过”转化为“能听懂、能认出、能回忆、能拼写、能在简单场景中使用”。

## 1.2 当前真实用户

| 项目 | 当前条件 |
|---|---|
| 年龄 | 8 岁，即将 9 岁 |
| 年级 | 小学三年级 |
| 基础词汇 | 基础词知道一些，稍难词较弱 |
| 自然拼读 | A3：`cat / ship / cake` 基本可自行拼读 |
| 主设备 | iPad |
| 次设备 | 手机 |
| 每日可用时间 | 约 30 分钟 |
| 家长参与 | 产品应支持孩子基本独立完成 |
| V1 目标 | 只给自己的孩子验证，不商业化 |

## 1.3 用户问题

传统单词表/卡片的问题：

- 单词之间缺乏语义关系。
- 识别题多，主动回忆少。
- 学完后缺少计划性再现。
- “会选”被误认为“会用”。
- 奖励和学习内容脱节。
- 8–9 岁孩子容易把它感知为作业，而非游戏。

## 1.4 设计命题

> 英语不是孩子要打败的 Boss；英语是她推进世界、解决问题的工具。

# 2. 产品目标与非目标

## 2.1 V1 核心目标

在 7 天 MVP 中验证：

1. 孩子是否愿意每天打开并完成 20–30 分钟学习游戏。
2. 30 个目标词在第 7 天能否达到较高识别保持率。
3. 是否能从四选一识别推进到部分主动回忆。
4. 哪类游戏最能同时兼顾兴趣和记忆。

## 2.2 量化成功指标

### Learning Retention
- 第 7 天，对已学 30 词的 **无中文提示识别正确率 ≥ 80%**。

### Active Recall
- 第 7 天，看到图片后主动说/拼出英文（允许宽松）的比例目标 **≥ 60%**。

### Voluntary Return
- 7 天内至少 4 天出现“非家长强制进入”或孩子主动要求继续玩的行为记录。
- 该指标 V1 可以由家长手工在报告页标记，不需要复杂遥测。

### Session Completion
- 目标：70% 以上日任务在 30 分钟内完成。

### Frustration Guardrail
- 连续错误 3 次后，系统必须降低难度或提供答案；不得让孩子卡死。

## 2.3 V1 明确不做

- 多账号 / 班级 / 教师后台
- 付费 / 商城 / 广告
- 排行榜 / 社交
- 云端同步
- 实时生成式 AI 对话
- 实时 AI 生成题目
- 复杂语音打分
- 471 词全部上线
- App Store 原生应用
- 后端数据库
- 服务端用户画像

`lion, zebra, tiger, panda, giraffe, monkey, fox, goat, bear, snake, hippo, elephant, rabbit, bee, turtle, frog, bird, ant, eagle, rhino, deer, feather, wing, claw, horn, tail, fur, paw, fly, swim`

# 4. 核心学习模型

## 4.1 学习循环

```text
SEE 看见
→ HEAR 听见
→ RECOGNIZE 识别
→ RECALL 主动回忆
→ USE 情境使用
→ REVIEW 延迟再现
```

中文不处于必经链路；推荐展示优先级：

```text
图片 → 英语声音 → 英文词形 → 必要时中文提示
```

## 4.2 单词掌握状态机

每个词有 6 个宏观状态：

| Level | 状态 | 定义 |
|---:|---|---|
| 0 | New | 从未接触 |
| 1 | Seen | 看过图/听过音/见过词形 |
| 2 | Recognized | 在图片/听音支持下能识别 |
| 3 | Recalled | 在弱提示下能主动想起 |
| 4 | Used | 能在简单任务/句子中正确应用 |
| 5 | Mastered | 跨天多次正确，达到长期记忆阈值 |

宏观状态不是简单由一次答对升级；必须结合证据维度。

## 4.3 证据维度

V1 内部记录至少：

- `listeningRecognition`：听音找到意义
- `visualRecognition`：图片 ↔ 词形
- `spelling`：拼写/补字母
- `activeRecall`：弱提示或无选项回忆
- `contextUse`：在简单指令/故事中使用
- `memoryStrength`：根据间隔与历史表现计算

儿童端不展示复杂分数；家长端可展示简化强弱。

# 5. 每日 30 分钟体验

默认目标 25–30 分钟；允许孩子提前完成。

## 5.1 Daily Adventure 结构

| 阶段 | 目标时长 | 内容 |
|---|---:|---|
| Warm Start | 2–3 min | 2–3 个旧词快速成功题 |
| New Discovery | 6–7 min | 5–7 个新词，图 + 音 + 轻交互 |
| Game Mix | 8–10 min | 2–3 种小游戏组合 |
| Memory Challenge | 5 min | 到期复习词，优先主动回忆 |
| Mission / Boss | 4–6 min | 综合场景，串联多个词 |
| Reward | <1 min | 世界发生可见变化 |

V1 每天新词上限：**7**。默认 5–6。

## 5.2 7 天 MVP 计划

| Day | 新词数 | 重点 |
|---|---:|---|
| 1 | 6 | 高熟悉度动物名，建立操作习惯 |
| 2 | 5 | 新词 + Day1 延迟复习 |
| 3 | 5 | 新词 + 引入身体特征 |
| 4 | 5 | 动物名与特征配对 |
| 5 | 5 | 引入动作 `fly / swim` 和综合指令 |
| 6 | 4 | 减少新词，大量混合复习 |
| 7 | 0 | Boss + retention + active recall 测试 |

具体词到天的分配可在内容任务阶段基于难度再冻结。

# 6. 页面与信息架构

## 6.1 页面清单

### P0 — Child Home
目标：孩子打开后几秒内知道“按哪里开始”。

必须有：
- 当前角色/宠物
- 世界视觉入口
- 大型 `PLAY / 继续冒险` 按钮
- 今日奖励进度（非常简化）

不得有：
- 密集菜单
- 学术化统计
- Unit / Lesson 表格
- 大量中文字

### P1 — World Map
V1 只真正开放 Animal Kingdom；其他世界可展示为远景/锁定区域。

必须有：
- 当前世界入口
- 已完成节点
- 下一任务明确高亮
- 返回 Home

### P2 — Daily Mission Intro
15 秒内完成任务引导：今天要帮助谁 / 找什么 / 修复什么。

### P3 — Game Shell
所有游戏复用统一外壳：
- 顶部极简进度
- 主场景
- 可重复播放发音按钮
- 退出/暂停入口（避免误触）
- 错误提示区

### P4 — Reward Moment
每次 Session 至少一个“世界发生变化”的奖励，例如：
- 解锁动物
- 修复栖息地
- 获得装饰
- 宠物获得物品

### P5 — Boss Mission
综合多个词，弱化选择题，强化动作/理解。

### P6 — Parent Gate
进入家长页前使用简单家长门槛，例如长按 2 秒 + 简单确认；避免孩子误进设置。

### P7 — Parent Dashboard
V1 显示：
- 今日时长
- 今日新词 / 复习词
- 已掌握 / 正在学 / 快忘词
- 最近错误/混淆词
- 7 天 retention
- 游戏偏好（基于完成与退出，不做复杂情绪推断）
- 数据导出/重置（重置需二次确认）

# 7. 核心游戏详细规格

V1 固定 5 种，不再扩展，直到 7 天验证完成。

## G1 Treasure Hunt / 听音寻宝

### 学习目标
`audio → meaning/object`

### 输入
- 目标词音频
- 场景内 4–8 个可点对象

### 流程
1. 播放 `Find the tiger.` 或仅 `tiger`。
2. 孩子点目标对象。
3. 正确：对象动画 + 再播一次词音 + 轻奖励。
4. 错误 1：不扣分，目标音频自动再播。
5. 错误 2：减少干扰/轻微高亮目标区域。
6. 错误 3：明确提示正确目标，记录 `assistedCorrect`。

### 验收
- iPad 触控目标最小建议 48 CSS px，主游戏对象尽量更大。
- 不允许因误触连续判错；点击后 300–500ms 内锁定输入。

## G2 Picture Match / 看图选词

### 学习目标
`image → written word`

### 难度
- Early：2–3 个选项
- Normal：4 个选项
- Review：混入易混词

### 规则
如果一个词连续成功，减少中文和图形辅助。

## G3 Word Builder / 拼词

### 学习目标
主动字形提取 + phonics 支持。

### Level
- L1：缺 1–2 个字母
- L2：字母块乱序
- L3：听音后从字母块构词

### 错误处理
不做红色大叉；先让错误字母轻微回弹，再播放音素/整词提示。

## G4 Put It Somewhere / 拖拽任务

### 学习目标
词汇关系与指令理解。

Animal MVP 示例：
- `Put the feather on the bird.`
- `Give the horn to the rhino.`
- `Which animal can fly? Move it to the sky.`
- `Which animal can swim? Move it to the water.`

V1 不追求完整语法教学，但句子必须自然、短、可理解。

## G5 Mini Story / Boss Mission

### 学习目标
把 3–6 个词放入同一情境，验证迁移。

示例：
1. `The eagle lost a feather.`
2. 找到 `eagle`。
3. 找到 `feather`。
4. `Put the feather near the eagle.`
5. `The eagle can fly.` → 将 eagle 拖到天空。

### 原则
Boss 的难度来自“组合”，不是来自生词和复杂句子。

# 8. 错误、提示与自适应

## 8.1 错误等级

- `independentCorrect`：无辅助正确
- `correctAfterReplay`：重播后正确
- `correctAfterHint`：提示后正确
- `revealed`：系统展示答案
- `wrong`：独立错误尝试

这些必须区分，因为“提示后答对”不能等同独立掌握。

## 8.2 连续错误保护

同题最多允许 3 次真实尝试：

```text
错 1 → 重播/重看
错 2 → 降低干扰 + 轻提示
错 3 → 展示答案 + 跟读/跟做
```

之后该词进入 2–8 分钟后的“软重测”，而不是立刻连续重复。

## 8.3 易混淆词

当 A 多次被错选为 B：
- 写入 `confusionPair` 计数。
- 后续生成 A/B 对比题。
- 家长页显示“最近容易混淆”。

# 9. 复习调度 V1

## 9.1 初始间隔

```text
首次学习
→ 约 10 分钟（同 session 或结尾）
→ 1 天
→ 3 天
→ 7 天
→ 14 天
→ 30 天
```

## 9.2 表现修正

每次 Attempt 先转换为 `quality`：

| 表现 | quality |
|---|---:|
| 独立主动回忆正确 | 1.0 |
| 独立识别正确 | 0.8 |
| 重播后正确 | 0.65 |
| 提示后正确 | 0.4 |
| 展示答案 | 0.15 |
| 错误 | 0 |

V1 调度规则：
- quality ≥ 0.8：进入下一标准间隔
- 0.4 ≤ quality < 0.8：保持当前阶段或缩短到约一半
- quality < 0.4：回到更短间隔，最早次日再次重点出现

不要在 V1 实现复杂 SM-2；优先可解释、可调试。

## 9.3 Mastered 条件

至少满足：
- 跨越 ≥ 7 天；
- 独立正确记录 ≥ 3；
- 至少包含一次 active recall 或 spelling；
- 最近一次质量 ≥ 0.8；
- 不能全部是同一天刷出的成绩。

# 10. 奖励设计

## 10.1 奖励目标

学习动作必须让游戏世界产生变化。

推荐：
- 解锁动物
- 获得栖息地装饰
- 修复桥/树/湖泊
- 获得角色衣饰

## 10.2 星星

可以使用星星作为“短反馈”，但星星不能成为唯一奖励。

### 禁止
- 断签清零
- 连续签到造成压力
- 输掉收藏品
- 错题扣大量资源
- 倒计时制造焦虑

# 11. 音频与发音

## 11.1 V1

每个目标词必须有：
- 标准英文发音音频
- 可重复播放
- 适当情况下有短指令音频

优先预生成并静态存放；不在孩子操作时请求生成 API。

## 11.2 孩子录音

V1 可选：本地录音 + 本地回放，不做云端评分。
若实现：
- 默认不保存长期；
- 明确录音状态；
- 离开页面后可自动删除临时 blob；
- 不上传。

---

# 12. 自然拼读策略

孩子已有 A3 自然拼读基础，因此：
- 拼写游戏可以较早出现。
- 不单独新增一套 phonics 课程。
- 在 Word Builder 中利用常见音形规律提供提示。
- 目标仍是“帮助记住当前词”，不是完成完整 phonics syllabus。

---

# 13. PWA / 离线体验需求

V1 必须：
- iPad Safari 可添加到主屏。
- 基本游戏在已下载后可离线运行。
- 学习进度写入本地 IndexedDB。
- 刷新页面不丢进度。
- 新版本升级不应清空学习数据。
- 静态资源更新失败时优先保留可玩的旧版本，不出现白屏。

# 15. UX 与儿童约束

- 横屏/竖屏均不应不可用；iPad 优先设计，可更偏横屏游戏体验。
- 关键交互必须 touch-friendly。
- 不能依赖 hover。
- 不能用纯颜色区分对错。
- 英文指令可配音；文字尽量短。
- 孩子端避免系统术语：`Review due`, `Mastery score` 等只出现在家长页。
- 动画用于反馈，不应拖慢答题节奏。
- 每个连续交互段建议 3–8 分钟，避免单一玩法 30 分钟。

# 17. MVP 验收标准

## Product
- [ ] 一个新安装用户可完成 Day 1 全流程。
- [ ] 7 天内容计划可连续推进。
- [ ] 30 词均可被调度、记录与复习。
- [ ] 至少 5 种游戏均复用统一 Attempt 数据模型。
- [ ] 连错 3 次不会卡死。
- [ ] 家长页可看到真实进度。

## Learning
- [ ] 不存在“看一次就自动 Mastered”。
- [ ] 提示后正确与独立正确分开记录。
- [ ] 至少一种游戏要求主动拼写/构词。
- [ ] Boss 至少组合 3 个以上已学词。

## Technical
- [ ] 本地 `pnpm dev` 可运行。
- [ ] 本地 `pnpm build` 可成功生成静态输出。
- [ ] Cloudflare Preview 可从 GitHub 自动构建。
- [ ] iPad Safari 刷新后不丢学习数据。
- [ ] PWA 可安装。
- [ ] 主要资源缓存后离线可玩。
- [ ] 不依赖运行时后端。

# 18. V1 后的决策门槛

只有 7 天测试结束后再决定：

1. 是否扩到第二世界。
2. 是否需要账号/云同步。
3. 是否需要服务端 API。
4. 是否需要真正的语音识别/发音评分。
5. 是否需要实时 AI 故事生成。
6. 是否商业化。

如果孩子不愿意主动继续玩，优先重做核心循环，不扩充词量。
